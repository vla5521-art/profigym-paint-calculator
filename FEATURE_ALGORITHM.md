# Алгоритм технологических элементов — PROFiGYM 1.7.0

## Границы

Алгоритм работает только после импорта `.stp`/`.step` в нормализованную B-Rep-модель OCCT. Он не анализирует имя файла, заранее записанные ответы или DTO фикстуры. Нативные форматы SolidWorks не поддерживаются.

Распознавание геометрии отделено от технологического решения:

1. `candidates.js` извлекает реальные B-Rep-грани, оболочки, рёбра, UV-границы, ориентации, площади и смежность.
2. `hole-recognizer.js` и `cavity-recognizer.js` создают геометрические элементы.
3. `rules.js` решает, можно ли исключить распознанный элемент.
4. `exclusions.js` объединяет подтверждённые контакты и features по исходным B-Rep-граням.

## Внутренний и наружный цилиндр

Наличие цилиндрической поверхности само по себе недостаточно. Кандидат отверстия обязан:

- принадлежать твёрдому телу;
- иметь B-Rep-ориентацию `reversed`;
- иметь замкнутый либо почти полный периодический UV-контур;
- иметь корректный радиус OCCT;
- иметь топологические связи с открывающими, переходными или донными гранями.

Наружный цилиндр эталонного вала имеет ориентацию `forward` и не создаёт feature. Неполный открытый цилиндрический контур классифицируется как `slot`, а не как отверстие.

Ось цилиндра определяется по двум точкам одной U-изолинии при `vMin` и `vMax`. Точка на оси восстанавливается из точки поверхности, ориентированной нормали и радиуса. Направление оси канонизируется, поэтому его знак не зависит от порядка обхода.

## Группировка граней

Цилиндрические участки объединяются, если одновременно выполняются:

- один `bodyId`;
- расстояние между осями не выше `CAD_FEATURE_AXIS_TOLERANCE_MM`;
- угловое отличие не выше `CAD_FEATURE_ANGLE_TOLERANCE_DEG`;
- осевые диапазоны соприкасаются в пределах допуска.

Плоская кольцевая грань между двумя участками сохраняется как `transitionFaceIds`. Маленькая плоская грань, площадь которой соответствует кругу минимального радиуса, сохраняется как `bottomFaceIds`. Коническая смежная грань сохраняется как переход зенковки.

`featureId` — SHA-256-отпечаток типа, `bodyId`, канонически отсортированных `faceIds`, размеров и оси. Случайный порядок обхода в идентификатор не попадает.

## Сквозность и глубина

- `through_hole`: цилиндрическая стенка не имеет связанного внутреннего дна; открывающие круговые контуры находятся на двух сторонах тела.
- `blind_hole`: стенка связана с внутренней плоской гранью малого кругового размера.
- глубина — полный осевой диапазон сгруппированных цилиндрических и конических участков;
- для сложного отверстия дополнительно сохраняются `segments`, `diametersMm` и `depthsMm`.

Дно входит в геометрический feature всегда, но по умолчанию не исключается (`CAD_HOLE_EXCLUDE_BOTTOM_FACE=false`).

## Ступени, зенковка и цековка

- три и более соосных цилиндрических диаметра: `stepped_hole`;
- два соосных цилиндрических диаметра с кольцевым переходом: `counterbored_hole`;
- цилиндр и смежный полнооборотный конус на той же оси: `countersunk_hole`.

Диаметр зенкованного отверстия соответствует фактическому диаметру внешнего контура конуса на поверхности детали, а не размеру режущего тела за пределами детали.

## Пересекающиеся отверстия

Отверстия сначала распознаются независимо. Если непараллельные оси одного тела проходят на расстоянии не больше суммы радиусов, оба элемента сохраняют отдельные feature ID и получают тип `intersecting_holes`. Автоматическое исключение запрещено: статус — `review_required`.

Пересечение не создаёт двойного вычитания, потому что итоговая площадь вычисляется по уникальным исходным `faceId`.

## Полости

### Закрытая

Внутренняя оболочка твёрдого тела считается `closed_internal_cavity`, если её точный AABB расположен строго внутри AABB тела по всем трём координатам. Все грани оболочки группируются в один feature. По умолчанию такая полость подтверждается автоматически.

### Открытая

После удаления уже занятых отверстиями граней ищутся связанные внутренние грани, которые:

- не лежат на внешней граничной плоскости AABB тела;
- соединены общими B-Rep-рёбрами;
- имеют внешний открывающий контур.

Такая группа получает тип `open_internal_cavity` и по умолчанию `review_required`.

## Rule engine

Правила применяются после распознавания. Значения по умолчанию:

| Правило | Значение |
|---|---:|
| автоматическое исключение | `true` |
| диаметр | `0.5…1000 мм` |
| глубина | `0.5…1000 мм` |
| сквозные отверстия | исключать |
| глухие отверстия | исключать |
| дно и плоские переходы | не исключать |
| зенковки | исключать |
| цековки | исключать |
| закрытые полости | исключать |
| открытые полости | ручная проверка |
| порог уверенности | `0.9` |
| допуск площади | `0.01 мм²` |
| допуск оси | `0.05 мм` |
| угловой допуск | `1°` |

Изменение правил задания повторно применяет rule engine к сохранённым распознанным элементам и не загружает STEP повторно. Ручное решение имеет приоритет до сброса.

## Объединение исключений

Простое сложение запрещено. Для каждой исходной грани строится одна запись:

- подтверждённый feature или ручное исключение занимает полную площадь грани;
- подтверждённые контактные B-Rep-патчи на грани объединяются OCCT;
- если полная грань уже исключена feature, контактный патч на ней второй раз не учитывается.

Так устраняются перекрытия:

- контакт ↔ отверстие/полость/manual;
- feature ↔ feature;
- contact ↔ contact;
- общая грань нескольких кандидатов.

Формулы:

```text
rawExcludedArea = rawContactExcludedArea + rawFeatureExcludedArea
overlapArea = rawExcludedArea - uniqueConfirmedExcludedArea
paintableArea = totalArea - uniqueConfirmedExcludedArea
```

Результат ограничивается снизу нулём. Превышение полной площади сверх допуска вызывает `FEATURE_AREA_OVERFLOW`.

## Ограничения

- Подтверждены только геометрии из `test-models/features`.
- Резьбы, NURBS-отверстия, произвольные литейные каналы и проницаемость для конкретного окрасочного инструмента не моделируются.
- Пересекающиеся отверстия не подтверждаются автоматически.
- Открытая полость не считается недоступной автоматически.
- Неполная цилиндрическая канавка классифицируется как паз и требует проверки.
- 3D-выбор и визуализация относятся к этапу 5.
